 One still → a whole game-ready sprite set


  Approve one generated still. Get every action of the character, keyed, looped, timed and exported for your engine.



  Agent skills for Claude Code (plugin), Codex and Grok. The agent generates a master still with the best image route you have, makes one image-to-video clip per action from it, and deterministic Python tools gate, key, register, loop, retime, finish and package every action for Godot, Aseprite or a web game.



  
    
      
      
      1. One approved master still
      
      Generated by the local Codex CLI (image_gen), take 1 of 3.
    
    
      
      
      2. Six actions, one image-to-video clip each
      
      Grok image-to-video (local CLI), soft-matte keyed, registered, loops picked by measurement, one-shots retimed to game speed, HD finish with the colour lock. Real timing.
    
  



  
  
  3. In a scene: the packaged run, attack and idle over a generated background. The run speed is measured from the contact foot, so the feet do not slide. Every frame comes from the 2026-10-06 live run; nothing is mocked up.

 New: pixel looks, 1x sprites that follow a reference


  
  
  A whole fight from pixel-look sprites, rendered at 1x and shown at 2x: four 1x characters (masters of 33x55 to 87x86) and 14 sets with 168 drawings read back from image-to-video clips. The plate behind them is a generated painting brought down to 384x216 and 40 colours. The white hit flashes and the knight's fade are the demo's; nothing else is added.


An image model asked for pixel art paints a picture of pixels: blocks of uneven size (15 to 30 px in the picture below), 88,410 colours in one small figure, soft edges. Shrinking it does not help: resized plainly to the sprite's size it still has 1,033 colours. Hibit gets round this by never asking for pixel art. Pixel looks go the other way, for the classic small sprite that follows a look you like: the look is never described in words, one sprite you like is the reference for the whole cast, and the picture the model paints is read back onto a real grid. pixel_look.py master finds the picture's own grid, takes one flat colour from every block, keeps the figure's proportions, brings the colours down to a palette and closes the outline by rule. What comes out can be counted: 33x55 pixels, 48 colours, alpha 0 or 255, a 2.5 KB PNG.

Real AI pixel game sprites: pixel looks and hibit

Ask an image model for pixel art and it paints a picture of pixels: blocks of uneven size, 88,410 colours in one small figure, soft edges. This release gives your agent two ways to real pixel art, in Claude Code, Codex and Grok:

- Pixel looks (new in 0.6.0): classic small sprites that follow a reference. The picture the model paints is read back onto a real grid.
- Hibit (0.5.0, announced here for the first time): high-bit pixel art. The model paints only a flat, lineless master and the Forge computes every pixel.
