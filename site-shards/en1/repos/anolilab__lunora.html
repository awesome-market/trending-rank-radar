 What is Lunora?

Lunora gives you Convex-style DX on infrastructure you control. You write type-safe queries, mutations, and actions in TypeScript. In production, Lunora deploys them as Cloudflare Workers: Durable Objects hold real-time state, D1 handles SQL, R2 stores blobs, and Queues run jobs. Nothing runs on servers we operate; the production stack lives in the Cloudflare account you already pay for. See Where it runs for the other targets.

Lunora is Vite-first. The dev loop, codegen, and client bindings plug into a Vite project through @cloudflare/vite-plugin, so local dev runs on workerd, the same runtime as production. Rsbuild and Rspack projects get the same loop through @lunora/rspack, and a standalone CLI covers everything else.

 Quick start

bash
pnpm dlx lunorash@alpha init my-app
cd my-app
pnpm install
pnpm dev


 Alpha. The npm package is lunorash because the unscoped lunora name is taken; the CLI it installs is still called lunora. Install from the @alpha dist-tag and expect breaking changes until the first stable release (see Status).

 Prefer managed hosting, or just want one email when v1 is stable? Join the Lunora Cloud waitlist →

A fresh app has three files you edit:

ts
// lunora/schema.ts
import { defineSchema, defineTable, v } from "lunorash/server";

export default defineSchema({
    messages: defineTable({
        author: v.string(),
        body: v.string(),
        ts: v.number(),
    }),
});


ts
// lunora/messages.ts
import { mutation, query, v } from "./_generated/server";

export const list = query.query(async ({ ctx }) = ctx.db.query("messages").order("desc").take(50));

export const send = mutation.input({ author: v.string(), body: v.string() }).mutation(async ({ ctx, args }) = {
    await ctx.db.insert("messages", { ...args, ts: Date.now() });
});
