`react-window` is a component library that helps render large lists of data quickly and without the performance problems that often go along with rendering a lot of data. It's used in a lot of places, from React DevTools to the Replay browser.

## Components

### Grid

Renders data with many rows and columns.

ℹ️ Unlike `List` rows, `Grid` cell sizes must be known ahead of time.
Either static sizes or something that can be derived (from the data in `CellProps`) without rendering.

#### Required props

<table>
  <thead>
    <tr>
      <th>Name</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>cellComponent</td>
      <td><p>React component responsible for rendering a cell.</p>
<p>This component will receive <code>columnIndex</code>, <code>rowIndex</code>, and <code>style</code> props by default.
Additionally it will receive prop values passed to <code>cellProps</code>.</p>
<p>ℹ️ The prop types for this component are exported as <code>CellComponentProps</code></p>
</td>
    </tr>
    <tr>
      <td>cellProps</td>
      <td><p>Additional props to be passed to the cell-rendering component.
Grid will automatically re-render cells when values in this object change.</p>
<p>⚠️ This object must not contain <code>ariaAttributes</code>, <code>columnIndex</code>, <code>rowIndex</code>, or <code>style</code> props.</p>
</td>
    </tr>
    <tr>
      <td>columnCount</td>
      <td><p>Number of columns to be rendered in the grid.</p>
</td>
    </tr>
    <tr>
      <td>columnWidth</td>
      <td><p>Column width; the following formats are supported:</p>
<ul>
<li>number of pixels (number)</li>
<li>percentage of the grid&#39;s current width (string)</li>
<li>function that returns the column width (in pixels) given an index and <code>cellProps</code></li>
</ul>
<p>ℹ️ Percentage widths can&#39;t be resolved during server rendering unless a <code>defaultWidth</code> (or a pixel width via the <code>style</code> prop) is specified.</p>
</td>
    </tr>
    <tr>
      <td>rowCount</td>
      <td><p>Number of rows to be rendered in the grid.</p>
</td>
    </tr>
    <tr>
      <td>rowHeight</td>
      <td><p>Row height; the following formats are supported:</p>
<ul>
<li>number of pixels (number)</li>
<li>percentage of the grid&#39;s current height (string)</li>
<li>function that returns the row height (in pixels) given an index and <code>cellProps</code></li>
</ul>
<p>ℹ️ Percentage heights can&#39;t be resolved during server rendering unless a <code>defaultHeight</code> (or a pixel height via the <code>style</code> prop) is specified.</p>
</td>
    </tr>
  </tbody>
</table>

#### Optional props

<table>
  <thead>
    <tr>
      <th>Name</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>className</td>
      <td><p>CSS class name.</p>
</td>
    </tr>
    <tr>
      <td>dir</td>
      <td><p>Indicates the directionality of grid cells.</p>
<p>ℹ️ The directionality of an ancestor element can&#39;t be detected during server rendering;
specify this prop explicitly for server-rendered right-to-left grids.</p>
<p>ℹ️ See HTML <code>dir</code> <a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/dir">global attribute</a> for more information.</p>
</td>
    </tr>
    <tr>
      <td>style</td>
      <td><p>Optional CSS properties.
The grid of cells will fill the height and width defined by this style.</p>
</td>
    </tr>
    <tr>
      <td>children</td>
      <td><p>Additional content to be rendered within the grid (above cells).
This property can be used to render things like overlays or tooltips.</p>
</td>
    </tr>
    <tr>
      <td>columnKey</td>
      <td><p>Grids use the column index as a <code>key</code> by default.
This prop can be used along with the <code>rowKey</code> prop to provide a custom <code>key</code> value.</p>
<p>ℹ️ Custom keys can ensure better UX for sortable or filterable grids,
particularly if your cell components are stateful.
Refer to the <a href="https://react.dev/learn/rendering-lists#keeping-list-items-in-order-with-key">React documentation</a> for more info.</p>
<p>⚠️ This prop cannot be auto-memoized because it is called during render.
It is important to always <code>useCallback</code> for this prop; do not use an inline function.</p>
</td>
    </tr>
    <tr>
      <td>defaultHeight</td>
      <td><p>Default height of grid (in pixels) for initial render, before its actual height has been measured.</p>
<p>ℹ️ Grids can&#39;t be measured during server rendering, so this value determines how many rows are server rendered.
It&#39;s recommended to set this to the expected height of the grid (or to specify a pixel height via the <code>style</code> prop).</p>
</td>
    </tr>
    <tr>
      <td>defaultScrollLeft</td>
      <td><p>Initial horizontal scroll offset (in pixels) of the grid.
This value is only applied once, when the grid first mounts with at least one column.</p>
<p>ℹ️ Server-rendered HTML can&#39;t be pre-scrolled, so server rendering always starts at the first column;
the default scroll offset is applied once the grid hydrates.</p>
<p>⚠️ If the grid can&#39;t be scrolled that far when the offset is applied (e.g. it is hidden with <code>display: none</code>,
or uses percentage column widths before its width has been measured), the offset is clamped or ignored and not retried.
Specify a <code>defaultWidth</code> (or a pixel width via the <code>style</code> prop) when using percentage column widths.</p>
</td>
    </tr>
    <tr>
      <td>defaultScrollTop</td>
      <td><p>Initial vertical scroll offset (in pixels) of the grid.
This value is only applied once, when the grid first mounts with at least one row.</p>
<p>ℹ️ Server-rendered HTML can&#39;t be pre-scrolled, so server rendering always starts at the first row;
the default scroll offset is applied once the grid hydrates.</p>
<p>⚠️ If the grid can&#39;t be scrolled that far when the offset is applied (e.g. it is hidden with <code>display: none</code>,
or uses percentage row heights before its height has been measured), the offset is clamped or ignored and not retried.
Specify a <code>defaultHeight</code> (or a pixel height via the <code>style</code> prop) when using percentage row heights.</p>
</td>
    </tr>
    <tr>
      <td>defaultWidth</td>
      <td><p>Default width of grid (in pixels) for initial render, before its actual width has been measured.</p>
<p>ℹ️ Grids can&#39;t be measured during server rendering, so this value determines how many columns are server rendered.
It&#39;s recommended to set this to the expected width of the grid (or to specify a pixel width via the <code>style</code> prop).</p>
</td>
    </tr>
    <tr>
      <td>gridRef</td>
      <td><p>Imperative Grid API.</p>
<p>ℹ️ The <code>useGridRef</code> and <code>useGridCallbackRef</code> hooks are exported for convenience in TypeScript projects.</p>
</td>
    </tr>
    <tr>
      <td>onCellsRendered</td>
      <td><p>Callback notified when the range of rendered cells changes.</p>
</td>
    </tr>
    <tr>
      <td>onResize</td>
      <td><p>Callback notified when the Grid&#39;s outermost HTMLElement resizes.
This may be used to (re)scroll a cell into view.</p>
</td>
    </tr>
    <tr>
      <td>overscanCount</td>
      <td><p>How many additional rows/columns to render outside of the visible area.
This can reduce visual flickering near the edges of a grid when scrolling.</p>
</td>
    </tr>
    <tr>
      <td>rowKey</td>
      <td><p>Grids use the row index as a <code>key</code> by default.
This prop can be used along with the <code>columnKey</code> prop to provide a custom <code>key</code> value.</p>
<p>ℹ️ Custom keys can ensure better UX for sortable or filterable grids,
particularly if your cell components are stateful.
Refer to the <a href="https://react.dev/learn/rendering-lists#keeping-list-items-in-order-with-key">React documentation</a> for more info.</p>
<p>⚠️ This prop cannot be auto-memoized because it is called during render.
It is important to always <code>useCallback</code> for this prop; do not use an inline function.</p>
</td>
    </tr>
    <tr>
      <td>scrollElement</td>
      <td><p>Element that scrolls the grid, for grids that scroll along with other content (e.g. the page):</p>
<ul>
<li>&quot;window&quot; to scroll with the page</li>
<li>an ancestor element that scrolls (e.g. stored with a <code>useState</code> ref callback); <code>null</code> until it has mounted</li>
</ul>
<p>The grid renders at its full height and only renders the rows (and columns) visible within the scroll element&#39;s viewport.
Its position within the scroll element is measured whenever it renders, scrolls, or resizes,
and whenever content before it is resized, inserted, or removed (e.g. an image loading above the grid).</p>
<ul>
<li>columns scroll with the scroll element too if the grid is as wide as its content (e.g. <code>style={{ width: &quot;max-content&quot; }}</code>);
otherwise the grid fills the width of its parent and its columns scroll within it</li>
<li><code>scrollToCell</code>, <code>scrollToColumn</code> and <code>scrollToRow</code> scroll whichever element scrolls each axis</li>
<li><code>defaultHeight</code> and <code>defaultWidth</code> are used as the viewport size until the scroll element has been measured (e.g. during server rendering)</li>
<li>percentage row heights and column widths are relative to the scroll element&#39;s viewport</li>
<li><code>defaultScrollLeft</code> and <code>defaultScrollTop</code> are ignored</li>
</ul>
<p>ℹ️ While the scroll element is <code>null</code>, the grid renders the first rows (as it does during server rendering).</p>
<p>⚠️ The grid&#39;s <code>onScroll</code> handler is only called when the grid scrolls its own columns;
listen to the scroll element&#39;s &quot;scroll&quot; events instead (or use the <code>useIsScrolling</code> hook).</p>
</td>
    </tr>
    <tr>
      <td>tagName</td>
      <td><p>Can be used to override the root HTML element rendered by the Grid component.
The default value is &quot;div&quot;, meaning that Grid renders an HTMLDivElement as its root.</p>
<p>⚠️ In most use cases the default ARIA roles are sufficient and this prop is not needed.</p>
</td>
    </tr>
  </tbody>
</table>

### List

Renders data with many rows.

#### Required props

<table>
  <thead>
    <tr>
      <th>Name</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>rowComponent</td>
      <td><p>React component responsible for rendering a row.</p>
<p>This component will receive an <code>index</code> and <code>style</code> prop by default.
Additionally it will receive prop values passed to <code>rowProps</code>.</p>
<p>ℹ️ Spread <code>ariaAttributes</code> onto the row element; they identify it as a row (e.g. so that dynamic row heights are measured reliably)</p>
<p>ℹ️ The prop types for this component are exported as <code>RowComponentProps</code></p>
</td>
    </tr>
    <tr>
      <td>rowCount</td>
      <td><p>Number of items to be rendered in the list.</p>
</td>
    </tr>
    <tr>
      <td>rowHeight</td>
      <td><p>Row height; the following formats are supported:</p>
<ul>
<li>number of pixels (number)</li>
<li>percentage of the list&#39;s current height (string)</li>
<li>function that returns the row height (in pixels) given an index and <code>rowProps</code></li>
<li>dynamic row height cache returned by the <code>useDynamicRowHeight</code> hook</li>
</ul>
<p>ℹ️ Percentage heights can&#39;t be resolved during server rendering unless a <code>defaultHeight</code> (or a pixel height via the <code>style</code> prop) is specified.</p>
<p>⚠️ Dynamic row heights are not as efficient as predetermined sizes.
It&#39;s recommended to provide your own height values if they can be determined ahead of time.</p>
</td>
    </tr>
    <tr>
      <td>rowProps</td>
      <td><p>Additional props to be passed to the row-rendering component.
List will automatically re-render rows when values in this object change.</p>
<p>⚠️ This object must not contain <code>ariaAttributes</code>, <code>index</code>, or <code>style</code> props.</p>
</td>
    </tr>
  </tbody>
</table>

<p>⚠️ If the list can&#39;t be scrolled that far when the offset is applied (e.g. it is hidden with <code>display: none</code>,

## Hooks

### useDynamicRowHeight

Creates a cache of measured row heights for lists whose rows can't be sized ahead of time.
Pass the returned value as the `rowHeight` prop of `List` (or the `itemSize` option of `useVirtualizer`);
rendered rows are then measured with a `ResizeObserver` and the list updates as their sizes change.

Rows that have not yet been measured use the `defaultRowHeight` (or `initialRowHeights`, if provided).

ℹ️ Dynamic row heights are more expensive than fixed sizes; prefer a number or function when row heights are known.

#### Parameters

<p>These values are used in place of <code>defaultRowHeight</code> until rows are rendered and measured,

### useIsScrolling

Tracks whether an element (or the window) is currently scrolling,
e.g. to render simplified content in place of rows that are expensive to render.

Pass the element that scrolls:
- a list or grid's own element (e.g. from `useListCallbackRef`)
- "window" or the scroll element, for lists and grids that use the `scrollElement` prop

Scrolling ends when the browser fires a "scrollend" event or,
in browsers that don't support that event, after no scroll events have been received for `delay` milliseconds.

ℹ️ Scrolling that starts and ends before React renders (e.g. an instant scroll) may not change this value.

⚠️ Changing this value re-renders any rows it is passed to (e.g. via `rowProps`) when scrolling starts and when it ends.
