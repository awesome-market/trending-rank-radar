Agent Autoloop

让你的命令行 Agent 在后台自己接活、自己跟进到底；平时不烦你，遇到拿不准的事才发卡片找你拍板。

 它解决什么问题？

平时我们用 Claude Code、Codex 这类命令行 Agent，大多是“人守着终端用”：你输一句话，盯着它跑，等它问你下一步；一旦关掉窗口或者人走开，事情就断了。

Agent Autoloop 是一个极轻量的自动化中台。它把任务调度做成一个零外部依赖的内核，把事件来源、Agent、通知通道，甚至代码上线流水线全部拆成可随时插拔的插件。

- 一台电脑、一条命令就能跑。 装在你的 Windows、Mac 或 Linux 上，不用买云服务器，也不用开放公网端口。
- 一行配置接新 Agent。 不需要 SDK，也不需要改 Agent 源码，能接收提示词并打印最后一条回复的命令行工具都能接。
- 没有后台界面。 需要你拍板时把卡片推到飞书、钉钉、企微、Slack、Discord 或桌面通知；想看全局进展，敲一行命令。

 上手

支持 Windows、macOS 和 Linux。需要 Node 24 或更新、Git，以及一个已经登录的命令行 Agent；macOS/Linux 还需要 curl，不需要 GitHub 账号。也可以把安装说明交给你的 Agent。

Windows PowerShell：

powershell
irm https://raw.githubusercontent.com/KKKKhazix/agent-autoloop/main/install.ps1 | iex


macOS / Linux：

bash
curl -fsSL https://raw.githubusercontent.com/KKKKhazix/agent-autoloop/main/install.sh | sh


安装和 agent-autoloop update 都装最新的 Release，那是通过了全部检查的版本。

装好后用你本机的 Agent 真实走一遍“提问 → 退出等回复 → 拍板 → 接着干完”：

bash
agent-autoloop try


下面是在终端里的真实输出：

text
事件发出去了，Agent 开始干活……

Agent 结束了这一轮，问了你一个问题。它现在不占进程、不花 Token。

【等你决定】1 试跑：选一个颜色
这是一次试跑，选哪个都行。
  1. 蓝色
  2. 绿色
回答：agent-autoloop answer 1 
答完运行 agent-autoloop status，能看到它接着把活干完。


交互终端里直接输入数字回车；非交互终端运行 agent-autoloop answer 1 2 选择“绿色”。再跑 agent-autoloop status，就能看到它接上刚才的会话并显示“你选了绿色，试跑通过”，还有今天和最近 7 天的轮数、Token 和费用（统计口径）。

 一件事怎么转起来

编号和上面的架构图一一对应：

1. 新事件进来。 早上 9 点的定时任务、GitHub 上新提的 Issue、业务系统报的错，都变成一条标准事件送进内核。
2. 按规则派活。 内核照你写的规则，决定交给哪个 Agent、去哪个目录干。同一件事排队时又来的消息，会合并成一轮处理。
3. 干完一轮就退出。 Agent 把结果写在最后一条回复里，进程直接退出。
4. 拿不准才问你。 碰到删数据、重启服务、花钱、对外发消息这类事，内核通过飞书或桌面通知发一张卡片给你。等你回复期间，它不占后台进程，也不消耗 Token。
5. 点一下，接着干。 你选完，它接上原来的对话，把剩下的活干完。

能自己搞定的事走图上方的自动闭环：直接办完，或者约个时间（比如半小时后）再醒来复查，全程不打扰你。

 日常怎么配？

 写一份规则（rules.json）

不需要写胶水代码。打开 ~/.agent-autoloop/rules.json，在 rules 里写清楚什么事、交给谁、在哪个目录干。to 填 agents 里已有的名字。比如每天早上 9 点写早报：

json
{
  "name": "早报",
  "when": { "cron": "0 9   " },
  "to": "codex",
  "cwd": "~/notes",
  "prompt": "整理昨天的笔记和提交，写今天的早报。"
}


外部事件写法一样，只是要先接好来源。比如有人提新 Issue 时交给 Codex，先按说明在 sources 里登记 github：

json
{
  "name": "处理 issue",
  "when": { "source": "github", "types": ["issues.opened"] },
  "to": "codex",
  "cwd": "~/code/app",
  "skill": "handle-issue",
  "parallel": 3
}


agent-autoloop pause 、resume  暂停和恢复一条规则，暂停期间到点不跑、来事件不接也不排队，恢复后不自动补跑；恢复时会列出暂停期间跳过的事件，照着给出的 agent-autoloop replay  --since  一次补跑，每条只补一次。agent-autoloop run  立即跑一轮。这些记在中台的日志里，不改 rules.json。agent-autoloop runs [规则] 列出做完的轮次，--before  往前翻，拿到编号再用 agent-autoloop why  看来龙去脉。

保存后几秒内自动生效，可以运行 agent-autoloop check 检查，agent-autoloop check  检查一份草稿，不碰正在跑的中台；agent-autoloop rules explain [文件] 看生效的规则和下次定时（也可以指定一份草稿），agent-autoloop emit  --dry-run 预演一条事件会派给谁（不连接中台、不写日志）。就算改错了，或者文件被删、读不到，系统也会继续按旧规则跑，并发卡片提醒你。

 Agent 怎么跟中台配合？

Agent Autoloop 1.8.3 v1.8.3 2026-11-13
更新内容

- 卡片写明来源：飞书卡片、桌面通知、所有 Webhook 平台、卡片网页和 status 的待决定列表，都在标题下写出是哪条规则问的；标题本身就是规则名时不重复。
- Token 统计口径统一：各家 Agent 的输入都算上缓存，status 写出其中缓存占多少（如“1.3 亿 Token（其中缓存 96%）”），/v1/state 的 spending 多一个 cached。升级前记下的 Claude、DSH 轮次仍是旧口径，一周后自然对齐。
- 规则的 elsewhere 登记项可以写可选的 model 和 effort，随 /v1/state 带出，显示别处定时任务的客户端不必再借用 Agent 的设置。退回旧版本前先把这两个字段从规则里去掉。
- 飞书：兼容旧版 lark-cli（如 1.0.66），首次发送卡片不再一直失败。
- GitLab：评论事件沿用所属 Issue / MR 的事项编号，不同对象的评论不再混进同一事项。
- 接单程序：找不到某个 Agent 程序时不再记住这个结果，程序装回来后不用重启就能用。
