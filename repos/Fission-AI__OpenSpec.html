What do the specs actually look like?

Plain Markdown — requirements with concrete scenarios, no special syntax to learn. Here's what goes in the specs/ folder created above:

markdown
 ADDED Requirements

 Requirement: Theme selection
The app SHALL let users switch between light and dark themes,
defaulting to the system preference.

 Scenario: User toggles dark mode
- WHEN the user clicks the theme toggle
- THEN the app switches to dark mode and persists the choice

 Why teams adopt OpenSpec

Solo, OpenSpec keeps you and your AI honest on a single repo. On a team, the hard part moves: a feature spans the API server, the web app, and a shared library; requirements are owned by one team and consumed by others; planning starts before any code exists.

Stores are the answer — planning in a repo of its own. The same openspec/ shape you already know (specs and changes), shared by git push like anything else. One source of truth your whole team and every coding agent can read, across every repo.

- Cross-repo features — one change, one plan, even when the code lands in three repos.
- Shared requirements — a platform team owns the specs; product teams reference them read-only, right where their coding agent can read them. No drifting wiki.
- Plan before code — capture the plan in the store now; the code repos catch up later.

 Stores are in beta. Start with the Stores guide.

v2.0.0 - Skills in .agents/skills, /opsx commands removed v2.0.0 2026-11-11
OpenSpec 2.0

OpenSpec now installs skills in .agents/skills/ instead of keeping a separate copy for each coding agent. Tools that don't read this folder, like Claude Code and Kiro, get links to the same skills.

We're also removing the /opsx: slash commands. Each command already has a matching skill, so there's no need to maintain both.

The OpenSpec workflows themselves haven't changed.

 What changed

- Skills are installed in .agents/skills/. Every tool uses the same skills, without duplicate files across folders.
- /opsx: commands are removed. For example, /opsx:propose becomes /openspec-
