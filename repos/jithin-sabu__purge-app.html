 本应用的简体中文界面基于 @zihua-zhang 的社区翻译（Purge-zh）。如果本文与英文 README 有出入，请以英文 README 为准。

 Purge 现在支持英文、简体中文、俄文和土耳其文，并跟随 macOS 的系统语言。你也可以在“系统设置  通用  语言与地区  应用程序”中单独为 Purge 设置语言。

你的 Mac 会悄悄积累大量缓存和垃圾文件，你既看不到，也从没要求过它们存在。Purge 会找出这些文件，标出哪些是安全的，并一键清理。

 [!NOTE]
 文件和文件夹默认会移到废纸篓，Purge 从不清空废纸篓，所以在你自己清空之前都可以放回去。以下内容会被永久移除：iOS 模拟器和模拟器运行时（通过 Xcode 的 simctl）；Xcode 可选的 Metal 工具链（通过 xcodebuild -deleteComponent，项目需要时 Xcode 会重新下载）；Time Machine 本地快照（通过 tmutil，Purge 会保留最新的一张和上次备份留下的那张）；macOS 27 上的 Apple 智能模型（由 Apple 的资源服务释放，之后可以在 Purge 里重新下载）；以及你在检查面板中选择交给包管理器卸载的命令行工具和 Homebrew cask 应用。Docker Desktop 的文件夹会移到废纸篓。Purge 不会执行 docker system prune。

你不需要了解其中的细节也能使用。不过，如果你想自己核对，每个项目都附有通俗易懂的说明和安全标签，所以不会有任何你事先看不到、验证不了的内容被动到。

 功能

 概览（Overview）

- 空间都去哪了：用一条横条展示整个磁盘。已用、可用和总容量直接取自磁盘卷，因此与系统设置中显示的一致。应用缓存、开发工具、大文件、已安装的应用以及已删除应用的残留文件，各占一段，其余部分显示为其他内容
- 每个类别一行，显示其大小和占磁盘的比例。点击某一行即可打开对应的标签页
- 其他内容也可以打开。点击该行会打开一个页面，显示其中有什么：顶部是四个数字，说明你能对这些空间做什么；下方是一张地图，每个分组是一个框，里面按占用空间画出它最大的文件夹，并按类型着色。类型包括：可在其他应用中释放的空间（照片、邮件、Steam、废纸篓）、你自己的文件（项目、文稿）、Purge 认为删除不安全而不去碰的内容（不在清单上的缓存、没有已安装应用认领的应用数据），以及由 macOS 管理的内容。把指针移到某个方块上会显示它的名称，点击可查看它是什么，并提供“在访达中显示”或所属应用自带的释放方式。它是只读的：这里的任何操作都不会移动文件
- 扫描全部（⇧⌘R）会逐个扫描所有类别，一次只扫一个，让 Mac 保持流畅。打开 Purge 时，它也会自动执行同样的操作。大文件、应用列表和残留文件需要完全磁盘访问权限。没有该权限时，Purge 仍会扫描应用缓存和开发工具，并跳过受 macOS 保护的位置，例如沙盒应用的缓存
- 每个字节只统计一次：应用的缓存文件夹计入应用缓存，不会在该应用名下重复计算
- 藏在“系统数据”中：位于各类别下方的一张卡片，显示 macOS 计入“系统数据”的空间。其中的 时间机器快照 一行用来移除本地快照；在 macOS 27 上，它还包含 Apple 智能模型
- Apple 智能模型（macOS 27，Apple 芯片）：macOS 归入“系统数据”的设备端模型，系统没有提供移除它们的开关。移除 会通过 Apple 的资源服务释放它们，并安装一个描述文件（你只需批准一次），让它们不会再次下载。重新下载 会请你在系统设置中移除该描述文件，然后按你的 Siri 语言向 macOS 请求 Purge 移除的那些模型。显示的大小是 Apple 给出的数字；Purge 记录的是磁盘实际释放的空间

 应用缓存（App Caches）

扫描 ~/Library/Caches、沙盒容器缓存（需要完全磁盘访问权限）以及常见的系统垃圾文件：

- 每个应用一个缓存文件夹，带有易懂的名称、品牌图标，以及你想看时可以阅读的通俗说明
- 系统垃圾文件，例如应用日志、崩溃报告、macOS 安装器和残留的 macOS 更新文件
- Premiere Pro 和 After Effects 等创意类应用产生的大型媒体缓存
- 同一应用的重复缓存位置会合并为一行
- 结果会在找到时即时显示

 开发工具（Dev Tools）

一个视图中包含五个部分：

- 全局开发工具缓存：Xcode（Derived Data、Archives、DeviceSupport）、Homebrew、npm、pnpm、Yarn、CocoaPods、Gradle、Dart 和 Flutter 的 pub 缓存、Docker Desktop、VS Code、Cursor、JetBrains、Cargo、Terraform 等
- iOS 模拟器：每个已关闭的模拟器各占一行。正在运行的模拟器也会列出，以便计入它占用的空间，但无法选中
- 模拟器运行时：simctl 标记为可删除的运行时，每个一行
- Xcode 组件：Xcode 可选的 Metal 工具链（约 900 MB），在完整的 Xcode 列出它已安装时，通过 xcodebuild -deleteComponent 移除
- 开发项目：node_modules、Python 虚拟环境、Rust 的 target、Flutter 构建产物、Xcode 的 Pods、Android 的 .gradle 以及其他生成文件，按项目分组

模拟器、运行时和 Xcode 组件始终标为“先检查”。它们会被永久删除，不会移到废纸篓，各自的分区标题上也写明了这一点。

在 设置 → 清理 中，选择 项目闲置多久后视为过期（1 个月到 2 年，或显示全部），来控制显示哪些项目。时间从项目内任何内容最后一次变动算起，包括 git 活动，而不是看 node_modules 或 target 的日期。正在使用的项目，例如其中正运行着终端或开发服务器，或正在执行 git 命令，永远不会出现。

由 AI 编程工具（Cursor、Codex、Conductor、T3 Code 和 Claude Code）创建的 Git 工作树，只有在其仓库不再列出它们之后，才会出现在 孤立 Git 工作树（Orphaned Git Worktrees） 下
