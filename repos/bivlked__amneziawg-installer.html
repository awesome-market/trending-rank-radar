Install AmneziaWG 3.1 / 2.0 VPN on Ubuntu and Debian VPS

amneziawg-installer одной командой ставит свой VPN-сервер AmneziaWG на VPS с Ubuntu или Debian: модуль ядра, настройка сервера и клиенты с QR-кодами. Работает там, где WireGuard блокируют. Хватит VPS за $3, знать Linux не нужно.
One-command, self-hosted AmneziaWG 3.1 VPN for Ubuntu 24.04 / 26.04 and Debian 13, with AmneziaWG 2.0 for older clients and routers. Kernel-native DKMS, no Docker, no web panel, runs on any cheap VPS. English README

 🚀 Быстрый старт

bash
wget -O install_amneziawg.sh https://github.com/bivlked/amneziawg-installer/releases/latest/download/install_amneziawg.sh
chmod +x install_amneziawg.sh
sudo bash ./install_amneziawg.sh


 Что получится (на x86_64 с Ubuntu 24.04 / 26.04 или Debian 13): сервер AmneziaWG 3.1, настроенный под VPN (форвардинг, тюнинг ядра) и защищённый (фаервол UFW, если согласитесь), и два готовых клиента, my_phone и my_laptop: их конфиги, QR-коды и ссылки vpn:// лежат в /root/awg/. 3 команды, 2 перезагрузки по ходу (при каждом вопросе о перезагрузке ответьте y, после каждой запустите последнюю команду снова), около 20 минут. Для чистого Ubuntu/Debian VPS, не роутер и не shared-хостинг. Подробнее →

 Подключить устройство. Нужен клиент с поддержкой 3.1: на Android - WG Tunnel или AmneziaWG, на iPhone - AmneziaWG (отсканируйте QR my_phone.png), на Mac - AmneziaWG (импорт .conf), на Windows - AmneziaWG (импорт my_laptop.conf), на любой платформе - Amnezia VPN (ссылка vpn://), на Linux - через awg-quick. Как забрать файлы с сервера - в разделе После установки; новое устройство потом - одна команда add.

 Есть роутер на стоковой прошивке, Hiddify или давно не обновлявшиеся приложения? Добавьте к последней команде --protocol=2.0, почему. На 32-битном ARM и на штатном Debian 12 установщик сам поставит 2.0.

v6.3.1 - модуль ядра сам пересобирается после обновления 24.04 HWE до 26.04; адрес выхода сверяется и с именем входа; генератор не берёт S4 = 16.

 Изменено

- Генератор параметров не выбирает S4 = 16. В профиле 2.0 пакет данных длиной S4 + 32 + 16k байт при S4 = 16 кратен 16 при любой длине содержимого, как у обычного WireGuard, и этот признак длины остаётся на виду. Теперь новые установки берут S4 из того же диапазона без 16 (4-27 в профиле 2.0, 12-27 в 3.1). В 3.1 длину и так меняет ContentPaddingAddition, а 16 исключено, чтобы признак не вернулся без
